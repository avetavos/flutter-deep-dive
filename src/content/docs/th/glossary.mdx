ศัพท์ของ Flutter ครอบคลุมหลายชั้นพร้อมกัน: ตัวภาษา Dart เอง (null safety, record, pattern, class modifier) ที่ทุกชั้นอื่นเขียนอยู่บนมัน; สามต้นไม้ (widget, element, render) ที่อธิบายเรื่อง performance ได้เกือบทุกอย่าง; state management (`setState`, `InheritedWidget`, Riverpod, BLoC) ที่สร้างอยู่บน element tree นั้นโดยตรง; การนำทาง (`Navigator`, go_router) และ platform channel สำหรับออกไปนอก Dart; อัลกอริทึม layout แบบ constraints กับ pipeline paint/composite/raster ที่อยู่ใต้ทุกพิกเซล; และเรื่อง tooling/production (testing, build, crash reporting) ที่เปลี่ยน widget tree ให้กลายเป็นแอปที่ส่งออกจริง เวลาอ่านบทเรียนแล้วเจอคำที่ไม่คุ้น หรือไม่แน่ใจว่ายังใช้ได้อยู่กับ Flutter 3.47.5 / Dart 3.13 ไหม ให้กลับมาดูที่นี่ — ทุกคำนิยามด้านล่างมาจากบทเรียนที่พิสูจน์ด้วยการรัน `flutter analyze`/`flutter test` จริง หรือ quote source/doc ของ SDK จริง ไม่ใช่จากความจำ

| `ValueNotifier` / `ValueListenableBuilder` | ทางเลือกที่แคบกว่าเมื่อเทียบกับการ "lift state up" แบบ `setState` ไร้เดียงสา: `ValueNotifier<T>` ถือค่าไว้นอกเส้นทาง rebuild ของ widget แล้วมีแค่ `builder` ของ `ValueListenableBuilder` เท่านั้นที่ rebuild เมื่อมันเปลี่ยน — พิสูจน์ตรง ๆ ด้วย build-counter test: `setState` แบบ lift ธรรมดาทำให้ `build` ของ sibling ที่ไม่ได้ฟังรันซ้ำทุกครั้ง (1→4 ตลอดสามการอัปเดต) ในขณะที่ sibling ของ `ValueListenableBuilder` ที่เทียบเท่ากันไม่ขยับจาก 1 เลย | [Stateless vs. Stateful](/flutter/th/widgets/stateless-vs-stateful/) |
