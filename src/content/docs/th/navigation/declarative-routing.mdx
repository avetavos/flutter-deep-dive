## ทำไม imperative push/pop ถึงพังตอนใช้จริง

Imperative navigation ทำงานได้ดีจนกว่าคุณจะต้องการ **deep link** เมื่อ user เปิด `myapp.com/orders/42` จาก cold start ไม่มีลำดับการเรียก `push` ที่เคยเกิดขึ้นเลย — คุณต้องสร้าง stack ทั้งหมด (Home → Orders → Order 42) ขึ้นมาใหม่จาก URL การทำแบบนั้นด้วยมือผ่าน `Navigator.push` นั้นยุ่งยากและมีโอกาสผิดพลาดสูง

ทางแก้คือทำให้ route stack เป็น **function ของ state แบบ declarative** — กำหนด URL หรือ app state ปัจจุบัน แล้วคำนวณ stack ออกมา นี่คือ Navigator 2.0 (บทก่อนหน้าครอบคลุมฝั่ง `Router`/`RouterDelegate`) เพราะ raw API ยาวมาก เกือบทุกคนเลยใช้ **`go_router`** (คอร์สนี้ pin ไว้ที่ 18.0.1 ใน probe; pub.dev ปัจจุบันตอนที่เขียนคือ 18.0.2 — การ pin เป็นแค่ snapshot ของ lockfile ไม่ใช่การอ้างว่า 18.0.1 เป็นตัวล่าสุด) ซึ่งเป็น package ทางการที่สร้างอยู่บนมัน

## การ config go_router

คุณประกาศ route ครั้งเดียวเป็น data `go_router` map path ไปยัง builder รองรับ typed path parameter และ sync browser URL อัตโนมัติบน web

```dart
final router = GoRouter(
  routes: [
    GoRoute(path: '/', builder: (context, state) => const HomeScreen()),
    GoRoute(
      path: '/orders/:id',                       // typed path parameter
      builder: (context, state) {
        final id = state.pathParameters['id']!;
        return OrderScreen(orderId: id);
      },
    ),
  ],
);

// Navigate by path — no manual stack juggling:
context.go('/orders/42');
```

`context.go('/orders/42')` ตั้ง location; router คำนวณ stack ใหม่ บน web, URL bar อัปเดตให้ตรงกัน และการ paste URL นั้นสร้างหน้าจอเดียวกันขึ้นมาใหม่ — deep linking ได้มาฟรี [คู่มือ deep-linking ของ Flutter เอง](https://docs.flutter.dev/ui/navigation/deep-linking) ครอบคลุมการต่อสาย platform-side (intent filter ใน `AndroidManifest.xml`, iOS Universal Links) ที่ต้องมีบน mobile — go_router จัดการฝั่ง Flutter route matching เมื่อ link มาถึงแอปคุณแล้ว

## Nested / shell route และ `StatefulShellRoute.indexedStack`

**shell route** ห่อ route กลุ่มหนึ่งด้วย UI ที่ใช้ร่วมกัน — แอป bottom-navigation แบบคลาสสิกที่ tab bar อยู่คงที่ในขณะที่เนื้อหาข้างในเปลี่ยน

```dart
ShellRoute(
  builder: (context, state, child) => ScaffoldWithNavBar(child: child),
  routes: [
    GoRoute(path: '/feed', builder: (context, state) => const FeedScreen()),
    GoRoute(path: '/profile', builder: (context, state) => const ProfileScreen()),
  ],
);
```

`ShellRoute` ใช้ `Navigator` ตัวเดียวร่วมกันทุก branch — สลับ tab ก็แค่ขยับภายใน stack *เดียวกัน* ดังนั้น route ที่ push ไว้ใต้ `/feed` จะหายไปทันทีที่คุณออกจาก branch นั้น สำหรับแอป bottom-nav ที่ **แต่ละ tab ต้องมี back-stack เป็นของตัวเองอิสระจากกัน** (สลับไป Profile, เจาะลึกเข้า Settings, สลับกลับ Feed, สลับกลับ Profile — Settings ควรยังอยู่) ทางแก้คือ `StatefulShellRoute.indexedStack`: มันให้ทุก branch มี **`Navigator` ของตัวเองแยกกัน** และเก็บทุกตัวไว้ให้ยังทำงานพร้อมกันใน `IndexedStack` — แสดงแค่ `Navigator` ของ branch ที่ active อยู่เท่านั้น แต่ไม่มีตัวไหนถูก dispose เพราะการสลับ tab เลย

```dart
// lib/shell_app.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

GoRouter buildShellRouter() => GoRouter(
  initialLocation: '/a',
  routes: [
    StatefulShellRoute.indexedStack(
      builder: (context, state, navigationShell) =>
          ShellScaffold(navigationShell: navigationShell),
      branches: [
        StatefulShellBranch(
          routes: [
            GoRoute(
              path: '/a',
              builder: (context, state) => const BranchAScreen(),
              routes: [
                GoRoute(path: 'detail', builder: (context, state) => const BranchADetailScreen()),
              ],
            ),
          ],
        ),
        StatefulShellBranch(
          routes: [
            GoRoute(path: '/b', builder: (context, state) => const BranchBScreen()),
          ],
        ),
      ],
    ),
  ],
);

class ShellScaffold extends StatelessWidget {
  const ShellScaffold({super.key, required this.navigationShell});
  final StatefulNavigationShell navigationShell;

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: navigationShell,
      bottomNavigationBar: BottomNavigationBar(
        currentIndex: navigationShell.currentIndex,
        onTap: (index) => navigationShell.goBranch(index),
        items: const [
          BottomNavigationBarItem(icon: Icon(Icons.home), label: 'Tab A'),
          BottomNavigationBarItem(icon: Icon(Icons.settings), label: 'Tab B'),
        ],
      ),
    );
  }
}

class BranchAScreen extends StatelessWidget {
  const BranchAScreen({super.key});
  @override
  Widget build(BuildContext context) => Scaffold(
    body: Center(
      child: TextButton(
        onPressed: () => context.push('/a/detail'),
        child: const Text('A root — go to detail'),
      ),
    ),
  );
}

class BranchADetailScreen extends StatelessWidget {
  const BranchADetailScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Center(child: Text('A detail')));
}

class BranchBScreen extends StatelessWidget {
  const BranchBScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Center(child: Text('B root')));
}
```

## trap ของ `/pets/:id` เทียบ `/pets/new`

`go_router` match route **ตามลำดับที่ประกาศ** และใช้ตัวที่ match **ตัวแรก** — มันไม่ได้ให้ priority กับ path segment ที่เป็น literal เหนือกว่าตัวที่มี parameter โดยอัตโนมัติ ประกาศ route ที่มี parameter ก่อน sibling ที่เป็น literal แล้ว parameter จะกลืนมันไป

```dart
// lib/pets_router.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

/// BUGGY order: '/pets/:id' is declared BEFORE '/pets/new', so ':id' matches
/// "new" as a literal id — a real trap AI-generated route tables fall into.
GoRouter buildPetsRouterWrongOrder() => GoRouter(
  initialLocation: '/pets',
  errorBuilder: (context, state) => const NotFoundScreen(),
  routes: [
    GoRoute(path: '/pets', builder: (context, state) => const PetsListScreen()),
    GoRoute(
      path: '/pets/:id',
      builder: (context, state) => PetDetailScreen(id: state.pathParameters['id']!),
    ),
    GoRoute(path: '/pets/new', builder: (context, state) => const NewPetScreen()),
  ],
);

/// FIXED order: the literal segment '/pets/new' is declared BEFORE the
/// parameterized '/pets/:id' — first match wins, so the literal must come first.
GoRouter buildPetsRouterFixedOrder() => GoRouter(
  initialLocation: '/pets',
  errorBuilder: (context, state) => const NotFoundScreen(),
  routes: [
    GoRoute(path: '/pets', builder: (context, state) => const PetsListScreen()),
    GoRoute(path: '/pets/new', builder: (context, state) => const NewPetScreen()),
    GoRoute(
      path: '/pets/:id',
      builder: (context, state) => PetDetailScreen(id: state.pathParameters['id']!),
    ),
  ],
);

class PetsListScreen extends StatelessWidget {
  const PetsListScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Text('Pets list'));
}

class NewPetScreen extends StatelessWidget {
  const NewPetScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Text('New pet form'));
}

class PetDetailScreen extends StatelessWidget {
  const PetDetailScreen({super.key, required this.id});
  final String id;
  @override
  Widget build(BuildContext context) => Scaffold(body: Text('Pet id: $id'));
}

class NotFoundScreen extends StatelessWidget {
  const NotFoundScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Text('404 — route not found'));
}
```

```dart
  });
}
```

## Redirect เป็น auth guard และ `refreshListenable`

`redirect` รันก่อน route จะ build และส่ง user ไปที่อื่นได้ — เป็นที่ที่เหมาะสมสำหรับ authentication guard return path ใหม่เพื่อ redirect หรือ `null` เพื่อดำเนินต่อ ตามลำพัง `redirect` จะ re-run แค่ตอนที่ *มีการ navigate เกิดขึ้น* เท่านั้น — มันไม่มีทางรู้ว่า auth state ของคุณเปลี่ยน **ด้วยตัวเอง** (token หมดอายุ, login สำเร็จจาก background stream) `refreshListenable` ปิดช่องว่างนั้น: ส่ง `Listenable` อะไรก็ได้เข้าไป (ส่วนใหญ่คือ `ChangeNotifier`) แล้ว router จะ re-evaluate `redirect` ทุกครั้งที่ listenable นั้น notify — โดยไม่ต้องมีการเรียก navigate เองเลย

```dart
// lib/auth_redirect_router.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

class AuthNotifier extends ChangeNotifier {
  bool loggedIn = false;
  void logIn() {
    loggedIn = true;
    notifyListeners();
  }
}

GoRouter buildAuthRouter(AuthNotifier auth) => GoRouter(
  initialLocation: '/',
  refreshListenable: auth,
  redirect: (context, state) {
    final goingToLogin = state.matchedLocation == '/login';
    if (!auth.loggedIn && !goingToLogin) return '/login';
    if (auth.loggedIn && goingToLogin) return '/';
    return null;
  },
  routes: [
    GoRoute(path: '/', builder: (context, state) => const HomeScreen()),
    GoRoute(path: '/login', builder: (context, state) => const LoginScreen()),
  ],
);

class HomeScreen extends StatelessWidget {
  const HomeScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Text('Home (protected)'));
}

class LoginScreen extends StatelessWidget {
  const LoginScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Text('Login'));
}
```

```dart
// test/auth_redirect_router_test.dart
import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:my_app/auth_redirect_router.dart';

  testWidgets(
    'redirect sends a logged-out user to /login, and refreshListenable re-evaluates it on external state change alone',

      await tester.pumpWidget(MaterialApp.router(routerConfig: router));

        findsOneWidget,

      );
    },
  );
}
```

## `context.go` เทียบ `context.push` เทียบ `Navigator.push` แบบ imperative — ปนกันในแอปเดียว

ทั้งสามแบบอยู่ร่วมกันใต้ `MaterialApp.router` ได้ และพฤติกรรมต่างกันในแบบที่สำคัญ:

- **`context.go(path)`** ตั้ง *location* — stack ที่ได้คือสิ่งที่ route table ของ `go_router` บอกว่า location นั้นควรมี stack เป็นอะไร สำหรับ top-level sibling route สองตัว การไปจาก `/` เป็น `/detail` จะ **แทนที่** stack เลย ไม่มีอะไรข้างล่างให้ pop กลับไป
- **`context.push(path)`** push entry *เพิ่มเติม* ขึ้นบน stack ปัจจุบัน โดย `go_router` ติดตามมันในฐานะ `ImperativeRouteMatch` คู่กับ match แบบ declarative ปกติของมัน
- **`Navigator.of(context).push(...)`** push ตรงบน Flutter `Navigator` ที่อยู่ข้างใต้ — มันขยาย widget-tree stack เหมือนกับ `context.push` เป๊ะ แต่ `go_router` ไม่เห็นมันเลย ความรู้เรื่อง "location ปัจจุบัน" ของมันไม่ถูกแตะเลย เพราะ route นั้นไม่เคยผ่าน route matching เลย

```dart
// lib/mixed_navigation_router.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

GoRouter buildMixedRouter() => GoRouter(
  initialLocation: '/',
  routes: [
    GoRoute(path: '/', builder: (context, state) => const HomeScreen()),
    GoRoute(path: '/detail', builder: (context, state) => const GoDetailScreen()),
  ],
);

class HomeScreen extends StatelessWidget {
  const HomeScreen({super.key});
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Column(
        mainAxisSize: MainAxisSize.min,
        children: [
          TextButton(
            onPressed: () => context.go('/detail'),
            child: const Text('context.go to Detail'),
          ),
          TextButton(
            onPressed: () => context.push('/detail'),
            child: const Text('context.push to Detail'),
          ),
          TextButton(
            onPressed: () => Navigator.of(context).push(
              MaterialPageRoute<void>(builder: (context) => const ImperativeDetailScreen()),
            ),
            child: const Text('Navigator.push to Detail (imperative)'),
          ),
        ],
      ),
    );
  }
}

class GoDetailScreen extends StatelessWidget {
  const GoDetailScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Text('Detail (via go_router)'));
}

class ImperativeDetailScreen extends StatelessWidget {
  const ImperativeDetailScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Text('Detail (imperative Navigator.push)'));
}
```

```dart
// test/mixed_navigation_router_test.dart
import 'package:flutter/material.dart';
import 'package:flutter_test/flutter_test.dart';
import 'package:my_app/mixed_navigation_router.dart';

void main() {
  testWidgets(
    'context.go replaces the location (no back stack); context.push and imperative Navigator.push both grow the stack, but only context.push is known to go_router',
    (tester) async {
      final goRouter = buildMixedRouter();
      await tester.pumpWidget(MaterialApp.router(routerConfig: goRouter));
      await tester.tap(find.text('context.go to Detail'));
      await tester.pumpAndSettle();
      expect(find.text('Detail (via go_router)'), findsOneWidget);
      var navigator = tester.state<NavigatorState>(find.byType(Navigator).first);
      expect(navigator.canPop(), isFalse, reason: 'go() replaced the current location — / and /detail are siblings, not parent/child, so nothing is left to pop to');
      expect(goRouter.routerDelegate.currentConfiguration.uri.toString(), '/detail');

      final pushRouter = buildMixedRouter();
      await tester.pumpWidget(MaterialApp.router(routerConfig: pushRouter));
      await tester.tap(find.text('context.push to Detail'));
      await tester.pumpAndSettle();
      expect(find.text('Detail (via go_router)'), findsOneWidget);
      navigator = tester.state<NavigatorState>(find.byType(Navigator).first);
      expect(navigator.canPop(), isTrue, reason: 'push() adds a new entry on top — Home is still underneath');

      final imperativeRouter = buildMixedRouter();
      await tester.pumpWidget(MaterialApp.router(routerConfig: imperativeRouter));
      await tester.tap(find.text('Navigator.push to Detail (imperative)'));
      await tester.pumpAndSettle();
      expect(find.text('Detail (imperative Navigator.push)'), findsOneWidget);
      navigator = tester.state<NavigatorState>(find.byType(Navigator).first);
      expect(navigator.canPop(), isTrue, reason: 'the raw Flutter Navigator stack grew, same as context.push, at the widget-tree level');
      expect(
        imperativeRouter.routerDelegate.currentConfiguration.uri.toString(),
        '/',
        reason: "go_router's OWN known location is still / — it never saw this push; it went straight to the Navigator, bypassing route matching entirely",
      );
    },
  );
}
```

## Typed route ด้วย `go_router_builder`

`state.pathParameters['id']!` ที่พิมพ์เองเป็นการ lookup runtime ที่ key ด้วย `String` — พิมพ์ key ผิดแล้วได้ null-check crash ไม่ใช่ compile error `go_router_builder` (ปัจจุบัน: 4.5.0 บน pub.dev) generate `GoRouteData` subclass ที่ typed ต่อ route จาก annotation `@TypedGoRoute` ดังนั้น path parameter กลายเป็น field ของ constructor จริง ๆ

```yaml
# pubspec.yaml
dev_dependencies:
  go_router_builder: ^4.5.0
  build_runner: ^2.16.1
```

```dart
// lib/typed_routes.dart
import 'package:flutter/material.dart';
import 'package:go_router/go_router.dart';

part 'typed_routes.g.dart';

@TypedGoRoute<HomeRoute>(path: '/')
class HomeRoute extends GoRouteData with $HomeRoute {
  const HomeRoute();

  @override
  Widget build(BuildContext context, GoRouterState state) => const HomeScreen();
}

@TypedGoRoute<PetDetailRoute>(path: '/pets/:id')
class PetDetailRoute extends GoRouteData with $PetDetailRoute {
  const PetDetailRoute({required this.id});
  final String id;

  @override
  Widget build(BuildContext context, GoRouterState state) => PetDetailScreen(id: id);
}

class HomeScreen extends StatelessWidget {
  const HomeScreen({super.key});
  @override
  Widget build(BuildContext context) => const Scaffold(body: Text('Home'));
}

class PetDetailScreen extends StatelessWidget {
  const PetDetailScreen({super.key, required this.id});
  final String id;
  @override
  Widget build(BuildContext context) => Scaffold(body: Text('Pet $id'));
}
```

## Mental Model

`go_router` คำนวณ `Navigator` stack ทั้งหมดจาก **state ชิ้นเดียว**: location ปัจจุบัน (บวกกับ imperative push ใด ๆ ที่ซ้อนอยู่ข้างบน) `redirect` คือ pure function ที่ veto หรือเขียน location ใหม่ก่อนที่อะไรจะ build ได้ `refreshListenable` ก็แค่ "รัน pure function นั้นอีกครั้ง" ที่ถูก trigger ด้วยอะไรก็ได้ที่ไม่ใช่ navigation `StatefulShellRoute.indexedStack` ขยายไอเดียเดียวกันต่อ branch: แทนที่จะมี location เดียวสร้าง stack เดียว แต่ละ branch เป็นเจ้าของ location-to-stack mapping ของตัวเอง และ `IndexedStack` คือสิ่งที่ทำให้ทุกตัวยัง resident อยู่ ดังนั้นการสลับ branch คือ **การเปลี่ยนความมองเห็น** ไม่ใช่การ rebuild trap ของ ordering กับความต่างของ `context.go`/`push`/`Navigator.push` ทั้งคู่มาจากข้อเท็จจริงเดียวกัน: **`go_router` ก็แค่ list อีกอันที่ถูก evaluate จากบนลงล่าง และมันรู้จักแค่ path ที่มันได้ evaluate เท่านั้น**

## Trade-offs

| ตัวเลือก | ข้อดี | ต้นทุน |
| --- | --- | --- |
| `ShellRoute` | ง่าย, `Navigator` ตัวเดียวใช้ร่วมกัน | branch ไม่มี state/stack เป็นของตัวเองแยกกัน |
| `StatefulShellRoute.indexedStack` | แต่ละ branch เก็บ stack และ scroll/form state ของตัวเองข้ามการสลับ tab ได้ | widget tree ของทุก branch ยัง resident อยู่ (memory), setup มากกว่า |
| `redirect` เดี่ยว ๆ | ง่าย รันทุกครั้งที่ navigate | มองไม่เห็น state change ที่ไม่ได้ trigger จาก navigation |
| `redirect` + `refreshListenable` | ตอบสนอง auth/state change ได้โดยไม่ต้องเรียก navigate เพิ่ม | ต้อง wire object เพิ่มอีกหนึ่งตัว (`ChangeNotifier`) และดูแลให้ sync |
| `state.pathParameters['id']!` แบบพิมพ์เอง | ไม่มีขั้นตอน codegen | เป็น string-typed; พิมพ์ผิดคือ null-check crash ตอน runtime ไม่ใช่ compile error |
| typed route ของ `go_router_builder` | สร้าง path แบบ compile-time-safe, มีจุด lookup เดียวแทนที่จะกระจัดกระจาย | มี `build_runner` อยู่ในลูป, generated code คือโค้ดจริงที่ analyzer ตรวจ |
| ปน `context.push`/`context.go` กับ `Navigator.push` ดิบ ๆ | ไม่มี — นี่คือ trap ไม่ใช่ตัวเลือก | go_router หลุด track หน้าจอที่ push แบบ imperative; URL/state อาจ drift ไปจากสิ่งที่แสดงอยู่จริง |

## Common Misconceptions

- **"`ShellRoute` กับ `StatefulShellRoute.indexedStack` พฤติกรรมเหมือนกัน แค่ syntax ใหม่กว่า"** ไม่จริง: `ShellRoute` ใช้ `Navigator` ตัวเดียวร่วมกันทุก branch (สลับ tab ไม่เคยรักษา sub-route ที่ push ไว้); `StatefulShellRoute.indexedStack` ให้แต่ละ branch มีของตัวเอง พิสูจน์แล้วข้างบนด้วย Detail screen ที่รอดจากการสลับ tab
- **"go_router เลือก route ที่ specific กว่าเหนือกว่า route ที่มี parameter โดยอัตโนมัติ"** ไม่จริง — มันคือ first-match-in-declaration-order พิสูจน์แล้วข้างบน (`/pets/:id` ที่ประกาศก่อนกลืน `/pets/new` จริง ๆ)
- **"`redirect` เดี่ยว ๆ ก็พอสำหรับ auth guard ที่ต้องตอบสนองต่อ login state ที่เปลี่ยนใน background"** `redirect` re-run แค่ตอน navigate เท่านั้น ถ้าไม่มี `refreshListenable` การ login ที่เสร็จจาก background stream จะทิ้ง user ไว้ที่ `/login` จนกว่าจะ trigger navigation *อะไรก็ได้*
- **"`context.go` กับ `context.push` ใช้แทนกันได้ แค่ verb ต่างกัน"** `go` แทนที่ stack ทั้งหมดของ location ปัจจุบัน (พิสูจน์แล้วข้างบน: `canPop()` เป็น `false`); `push` เพิ่มขึ้นบน (`canPop()` เป็น `true`) — UX ของปุ่ม/gesture back ต่างกันมาก
- **"เพราะ go_router คือ routing ที่ config ให้ `MaterialApp.router` แล้ว `Navigator.push` ใด ๆ ในแอปนั้นจะถูกมันติดตามโดยอัตโนมัติด้วย"** พิสูจน์แล้วว่าไม่จริงข้างบน: `Navigator.push` แบบ imperative ขยาย widget-tree stack จริง แต่ `currentConfiguration.uri` ของ `go_router` เองไม่เปลี่ยนเลย — มันข้าม route matching ของ go_router ไปทั้งหมด
